## Objetivo

Cuando un modelo «llama a una herramienta», en realidad **propone** un nombre y unos argumentos en JSON. Esa propuesta puede ser incorrecta: un argumento que falta, un número escrito como texto, un valor fuera de los permitidos. Ejecutarla sin comprobar puede romper el agente, o algo peor. El **registro de herramientas** es la capa que (1) describe las herramientas al modelo con un esquema, (2) **valida** lo que el modelo propone y (3) devuelve los errores como **observación** para que el modelo pueda corregirse.

## Esquema simplificado

Cada herramienta lleva un esquema como el de la API de tool calling:

```python
{"type": "object",
 "properties": {"valor": {"type": "number"}, "unidad": {"type": "string", "enum": ["km", "mi"]}},
 "required": ["valor", "unidad"]}
```

Tipos admitidos: `string`, `integer`, `number`, `boolean`, `array` y `object`. Se admite `enum` y no se permiten argumentos no declarados.

## Qué tienes que hacer

Implementa la clase `ToolRegistry`:

- `register(name, func, description, parameters)`: guarda la herramienta; si el nombre ya existe lanza `ValueError`.
- `specs()`: lista de `ToolSpec` (`ragkit.agents`) en orden de registro, lo que se le presenta al modelo.
- `validate(name, args)`: lista de errores (vacía si todo es correcto). Los mensajes son **exactos**:
  - `herramienta desconocida: <nombre>`
  - `falta el argumento obligatorio: <arg>`
  - `argumento no esperado: <arg>`
  - `el argumento '<arg>' debe ser <tipo>`
  - `el argumento '<arg>' debe ser uno de <lista del enum>`

  Primero los obligatorios que faltan (en el orden de `required`) y después, en el orden de `args`, los demás. Un booleano **no** es un `integer` ni un `number`.
- `call(name, args)`: valida y ejecuta con `func(**args)`. Con errores de validación devuelve `{"ok": False, "error": "; ".join(errores)}`; si la función lanza una excepción, `{"ok": False, "error": "<Tipo>: <mensaje>"}`; si todo va bien, `{"ok": True, "result": valor}`.

## Un ejemplo para comprobar a mano

```python
registro.call("sumar", {"a": 2, "b": 3})   # {'ok': True, 'result': 5}
registro.call("sumar", {"a": "2"})
# {'ok': False, 'error': "falta el argumento obligatorio: b; el argumento 'a' debe ser integer"}
```

<Callout type="nota" title="Los errores son para el modelo">

El mensaje de error no es para el programador: es lo que el modelo leerá en la siguiente vuelta del bucle. Un mensaje concreto («el argumento 'a' debe ser integer») permite que el agente se corrija solo; «Error 500» no.

</Callout>
